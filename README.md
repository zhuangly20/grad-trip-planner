# GradTrip · 把散落的攻略变成能出发的行程

美团校招 Vibe Coding 附加题作品。GradTrip 面向毕业旅行团长：把来自小红书、群聊和朋友推荐的零散灵感，以及每位成员“不想错过的毕业心愿”，整理成一份按天安排、来源可回溯、可以发回群里确认的行程草案。

在线访问：<https://zhuangly20.github.io/grad-trip-planner/>

## 产品定位

这个产品不负责“发现更多攻略”，而是解决攻略已经很多、却始终无法形成共同方案的问题：

- 小红书等内容平台负责发现灵感；
- GradTrip 负责记录推荐人、来源和毕业心愿，并把选中的体验排入日期；
- 微信群继续负责讨论与确认，最终计划可以一键复制回去。

因此，核心用户是愿意把旅行组织起来的“团长”，不是要求全组成员注册并迁移到一个新平台。

## 核心功能

- 旅行信息：目的地、旅行名称、起止日期，自动生成 1–10 天的单目的地日程；
- 同行伙伴：添加、改名、移除伙伴，并用伙伴标记灵感来源；
- 灵感池：记录体验名称、推荐人、原始来源和一句话备注，支持编辑与删除；
- 毕业心愿：每位伙伴最多一个“不想错过的心愿”，输出前检查是否仍未安排；
- 按天排程：一键放入某天、调整顺序、移回灵感池；
- 成行检查：旅行骨架、日程内容、心愿遗漏和留白情况；
- 行程草案：实时生成可复制的文字计划，支持打印或保存 PDF；
- 本地持久化：刷新页面后继续编辑，数据仅保存在当前浏览器；
- 完整示例：一键载入成都毕业旅行示例，便于快速演示。

## 明确不做

为了保持场景聚焦和交付完整，当前版本刻意不提供：

- AI 攻略生成、网页内容抓取或路线优化；
- 跨设备组队、在线投票、聊天和“全员已确认”状态；
- 地图、实时开放时间、酒店/车票预订；
- 预算匹配、费用分摊和在线支付；
- 多旅行项目管理与云端同步。

页面上不会出现没有真实能力支撑的按钮或宣传文案。

## 关键边界处理

- 每位伙伴同一时间只能有一个毕业心愿，避免“心愿”失去约束力；
- 移除伙伴时明确提示会同步移除其推荐的灵感和心愿；
- 缩短有效日期时，受影响的安排会移回灵感池，不会被删除；
- 临时把某个日期清空时，已有日程会保留，恢复有效日期后仍可使用；
- 用户输入统一转义，避免把攻略标题中的 HTML 当作页面代码执行；
- 清空、覆盖示例、删除灵感和移除伙伴都需要二次确认。

## 技术实现

纯静态前端，无构建步骤、无外部运行依赖：

- `index.html`：官网、产品工作区和输出行程；
- `styles.css`：响应式视觉系统与打印样式；
- `app.js`：本地状态、日期/排程逻辑、心愿检查、复制与打印；
- 浏览器 `localStorage`：本地持久化。

## 本地运行

可直接打开 `index.html`，也可以在项目目录启动静态服务：

```bash
python -m http.server 4173 --bind 127.0.0.1
```

然后访问 <http://127.0.0.1:4173/>。
